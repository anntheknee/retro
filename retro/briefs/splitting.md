If `prepare` printed "input split into N pieces", `splits.json` maps `a` and/or `b` to piece files (`agent_a_1.json`, …) that replace `agent_a.json` / `agent_b.json`; C is never split. Spawn one `retro-worker` agent per piece, in the same message as the others, each told to read its piece's brief (`brief_a_1.md`, …). The piece brief already asks it for problems seen in only 2 of its Sessions (one line each, with the Session ids), so the reconcile agent can add them up across pieces, and for verdict rows that cover only its own Sessions. Then, per split group, spawn one `retro-worker` reconcile agent with `model: opus`: give it the pieces' returned drafts (verdict rows and Findings); it merges duplicates, combines their evidence before any frequency threshold (3 Sessions in one piece plus 3 in another counts as 6, so a problem below the bar in each piece can clear it), re-letters solutions (at most 3 per Finding) and returns one set of verdict rows and Findings for the main merge. Every piece carries `previous_findings`. The reconcile agent gives one verdict per previous Finding across all pieces (the problem came back in any piece: didn't work, or not adopted). A failed piece or reconcile agent is handled as `briefs/failures.md` says.
