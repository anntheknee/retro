`## Failed parts` lists every failed agent, `/insights` run and feed (from `errors` in `upstream.json` and `news_raw.json`), one line each, saying whether it was re-run ("re-run, succeeded", "re-run, failed", "re-run declined" or "not re-run" (feeds, `/insights`, `news`)). Never add a spending cap or a cost report.
- Usage limit (an agent's result says so): that isn't a failure. Tell the user which agents paused, and to type "continue" after the reset. On "continue", re-run only those agents, with the same prompts and the same input files in the temp folder; list nothing for them. Don't run `commit` while an agent is paused; if the re-run hits the limit again, pause again.
- Any other agent failure (crash, garbled output, timeout): offer one re-run of that agent and wait for approval. If the user declines, or the re-run fails, list it under Failed parts and go on. This covers the phase-2 web agent too. An `/insights` failure or a down feed isn't offered a re-run.
- A failure never stops the Retro or holds back the timestamp: still run `commit`. The one exception is when A, B and C all failed (after any re-run): don't run `commit`, `rm -rf` the temp folder `prepare` printed, say so, and leave the state as it was.
