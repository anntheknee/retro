Read `upstream.json` yourself and write `## Toolkit updates` in `draft.md`, one item per entry in `skills`, `synced`, `plugins` and `claude_code`, in the Finding layout with **What changed** in place of **Problem** and no category, project or origin in the heading (`### <n>. <item>`, numbered after the Findings in the numbering step). Each item says what changed since `since` (a skill's repo commits from `commits[<repo>]`, repo-wide headlines since `since`, a plugin's releases, Claude Code's versions; one line each for skills from the same repo, with the commits that touch it if the headlines show it), its `uses` in the Window, and the exact `update` command as the solution. A `removed upstream` skill says upstream deleted it, so no update comes, and the user is its only maintainer now. Claude Code's releases are also the upstream of built-in commands, bundled skills and agents; say which new releases matter to items the user used. Skip entries with nothing behind. `clis` lists installed CLIs: each `outdated_used` entry is a Toolkit update like the others (its `update` command; its changelog is read later). Each `unused_outdated` line goes verbatim under `## Toolkit updates` as a plain bullet after the numbered items, with no analysis and no uninstall advice. `owned` covers Owned Skills (a `metadata.upstream` list of `{repo, path, base}`), as ordinary Findings under `## Findings` (category `skills`, origin `via Retro`), weighed with the rest. Never merge, edit or run git:
- `tracked` with state `changed`: a "port this?" Finding naming the skill, the tracked source (`repo` `path`) and the `base`..HEAD range. Read the skill's own `SKILL.md`, then judge each changed file's `patch` (`commits` are repo-wide headlines, context only): raise only changes to content the skill kept, and skip dropped parts silently. State `removed upstream`: a Finding that upstream deleted the source, so the user is its only maintainer now.
- `edited_installs`: the install's files differ from its locked version, so a later `npx skills update` would overwrite the edit. A Finding to own it: a folder `~/.claude/skills/<skill>/` (a real copy of the edited files) with `metadata: {upstream: [{repo: <repo>, path: <path>, base: <base>}]}` and a row in the skills README, removing the symlink and the lock entry through `npx skills remove <lock_key>` only after the copy exists.
An install in `edited_installs` also listed under `skills` as behind gets no update command: `npx skills update` would overwrite the edit.
- `no_provenance`: real folders with no `metadata.upstream`; only the first Retro fills it, so later Retros never raise it again. Check `~/.claude/skills/README.md` for each; one Finding for those it records as copied from a repo (name each, with the source from the README), to add `metadata: {upstream: [{repo, path, base}]}` using the commit it names. Skills the README shows as written by the user need nothing.
A non-empty `errors` list goes under Failed parts. Changelog judgment beyond this comes later.
