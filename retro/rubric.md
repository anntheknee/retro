# Retro rubric

A rubric for problem categories (1) prompt quality, (2) context management, (3) using skills you have, and (8) turning repeated workflows into skills. Each item gives the practice, the anti-pattern a Retro can spot in a Session transcript, and the source. **Detect** marks whether plain code in the helper script can find the signal (`script`) or whether it needs LLM judgment (`LLM`). This follows the map's standing preference that the script does the heavy lifting.

The single principle under most of the rubric: "Claude's context window fills up fast, and performance degrades as it fills" (BP, intro). CE calls the same effect "context rot" and states the goal as "the smallest set of high-signal tokens that maximize the likelihood of your desired outcome."

## (1) Prompt quality

| # | Practice | Anti-pattern to spot | Detect | Source |
|---|---|---|---|---|
| P1 | Scope the task: name the file, the scenario, and the constraints. | Short, unanchored task prompts ("add tests", "fix the login bug", "improve this codebase") followed by broad Glob/Grep/Read sweeps or a clarifying round-trip. | script (prompt length, no path or `@` mention, many reads after it) + LLM | [BP#provide-specific-context-in-your-prompts](https://code.claude.com/docs/en/best-practices#provide-specific-context-in-your-prompts); [COST#write-specific-prompts](https://code.claude.com/docs/en/costs#write-specific-prompts) |
| P2 | Give Claude a check it can run (test cases, a build, a screenshot to compare) and ask it to iterate until the check passes. Ask for evidence, not an assertion of success. | The user is the verification loop: Claude says "done", then the user reports a failure. No test, build, or lint run before the turn ends. | script (no test/build Bash call before "done"; a user message after it reports an error) | [BP#give-claude-a-way-to-verify-its-work](https://code.claude.com/docs/en/best-practices#give-claude-a-way-to-verify-its-work); [PE "Provide verification tools"](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#workflows-across-multiple-context-windows) |
| P3 | Point to existing patterns and to sources ("look at HotDogWidget.php", "read the git history of X"). | Claude invents a new pattern, and the user then corrects it to "do it like the existing one". | LLM | [BP#provide-specific-context-in-your-prompts](https://code.claude.com/docs/en/best-practices#provide-specific-context-in-your-prompts) |
| P4 | Describe the bug: give the symptom, the likely location, and what "fixed" looks like. Paste the actual error. | "It's broken" or "the build is failing" with no error text, followed by Claude running commands to rediscover the error. | script (prompt has no error text; the next tool call reproduces it) + LLM | [BP table "Describe the symptom", "Address root causes"](https://code.claude.com/docs/en/best-practices#give-claude-a-way-to-verify-its-work) |
| P5 | Give rich input directly: `@file` references, pasted screenshots, URLs, piped data. | The user describes where code lives in prose ("the auth file somewhere in src") instead of using `@path`, or retypes log content by hand. | script (no `@` mentions; path-like words in prose) | [BP#provide-rich-content](https://code.claude.com/docs/en/best-practices#provide-rich-content) |
| P6 | Explore, then plan, then code. Use plan mode when the approach is uncertain, the change spans files, or the code is unfamiliar. Skip planning if you could describe the diff in one sentence. | A large multi-file change starts without exploring or planning, and the code is later thrown away or reworked. The inverse also counts: plan mode used for trivial one-line edits. | script (plan-mode entries vs. files edited) + LLM | [BP#explore-first-then-plan-then-code](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code); [COST#work-efficiently-on-complex-tasks](https://code.claude.com/docs/en/costs#work-efficiently-on-complex-tasks) |
| P7 | For larger features, have Claude interview you (AskUserQuestion), write a self-contained spec, then implement it in a fresh session. | A big feature is built from a one-line ask, then reshaped through many corrections. | LLM | [BP#let-claude-interview-you](https://code.claude.com/docs/en/best-practices#let-claude-interview-you) |
| P8 | Say what action you want. "Can you suggest changes" gets suggestions; "Change this function" gets edits. | The user asks for suggestions, gets a list, then says "ok, do it", which costs a wasted round-trip. | LLM | [PE#tool-usage](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#tool-usage) |
| P9 | Give the reason behind a constraint, not only the rule. Claude generalizes from the explanation. | Bare rules ("NEVER do X") that Claude then applies wrongly at the edges. | LLM | [PE#add-context-to-improve-performance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#add-context-to-improve-performance) |
| P10 | Use normal language, not shouting. Current models overtrigger on "CRITICAL: You MUST..." In CLAUDE.md, reserve "IMPORTANT" for the one line Claude keeps skipping. | ALL-CAPS or "CRITICAL/MUST" across many lines of prompts, CLAUDE.md, or skills. | script (regex over prompts and instruction files) | [PE#tool-usage](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#tool-usage) (dial back aggressive language); [BP#write-an-effective-claude-md](https://code.claude.com/docs/en/best-practices#write-an-effective-claude-md) |
| P11 | Use the "golden rule": a colleague with minimal context should be able to follow the prompt. | The prompt depends on unstated context from another Session or from the user's head ("do the thing we discussed"). | LLM | [PE#be-clear-and-direct](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#be-clear-and-direct) |
| P12 | Ask for minimal scope when Claude overbuilds. | Repeated user pushback such as "too much", "simpler", or "don't add X", with no standing instruction to stop it. This is a CLAUDE.md or output-style candidate. | script (keyword counts) + LLM | [PE#overeagerness](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#overeagerness) |

Caveat from BP ("Develop your intuition"): vague prompts are fine when exploring on purpose. Flag vagueness only when it led to rework or wasted reads.

## (2) Context management

| # | Practice | Anti-pattern to spot | Detect | Source |
|---|---|---|---|---|
| C1 | `/clear` between unrelated tasks. | **Kitchen sink session**: one Session switches topics (different files, repos, or goals) without a `/clear`. | script (`/clear` absent; topic shift by file-set change) + LLM | [BP#avoid-common-failure-patterns](https://code.claude.com/docs/en/best-practices#avoid-common-failure-patterns); [COST#manage-context-proactively](https://code.claude.com/docs/en/costs#manage-context-proactively) |
| C2 | After two failed corrections on the same issue, `/clear` and restart with a better prompt that includes what you learned. | **Correcting over and over**: 3+ consecutive user corrections on one issue in the same Session. | script (runs of correction-like user turns) + LLM | [BP#course-correct-early-and-often](https://code.claude.com/docs/en/best-practices#course-correct-early-and-often) |
| C3 | Course-correct early with `Esc`, and use `Esc Esc` or `/rewind` to roll back. Don't let a wrong direction run. | Long autonomous runs the user rejects at the end ("no, revert all that"), with no interrupt. "Undo"-style requests instead of `/rewind`. | script (interrupt markers, `/rewind` usage, "revert/undo" prompts) | [BP#course-correct-early-and-often](https://code.claude.com/docs/en/best-practices#course-correct-early-and-often); [BP#rewind-with-checkpoints](https://code.claude.com/docs/en/best-practices#rewind-with-checkpoints) |
| C4 | Use `/compact <focus>` before a long new task, or partial summarize via `/rewind`, instead of waiting for auto-compaction. When a fresh start is fine, `/clear` costs nothing, while `/compact` is itself a large request. | Repeated auto-compactions in one Session. Many `/compact` runs where a `/clear` would do. | script (compaction boundary records in JSONL) | [CW#when-your-context-fills-up](https://code.claude.com/docs/en/context-window#when-your-context-fills-up); [COST#why-usage-climbs-in-a-long-session](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session) |
| C5 | Put instructions that must persist into CLAUDE.md. Instructions given only in conversation are lost at compaction. | The user re-states the same instruction after a compaction, or across Sessions. | script (near-duplicate user instructions across the Window) + LLM | [MEM#instructions-seem-lost-after-compact](https://code.claude.com/docs/en/memory#instructions-seem-lost-after-compact); [CW#what-survives-compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction) |
| C6 | Add a CLAUDE.md entry when Claude makes the same mistake twice, or when you type the same correction you typed last Session. | The same correction recurs across Sessions in one project with no matching CLAUDE.md line. This overlaps categories 4 and 6. | script (cluster correction text by project) + LLM | [MEM#when-to-add-to-claude-md](https://code.claude.com/docs/en/memory#when-to-add-to-claude-md); [FO#build-your-setup-over-time](https://code.claude.com/docs/en/features-overview#build-your-setup-over-time) |
| C7 | Keep each CLAUDE.md under 200 lines, concrete, and conflict-free. For each line, ask "would removing this cause mistakes?" Move procedures to skills and path-specific guidance to `.claude/rules/` with `paths:`. Imports don't reduce cost. | **Over-specified CLAUDE.md**: a file over 200 lines, vague rules ("write clean code"), or contradictions. Claude ignores a rule that exists, or asks something CLAUDE.md answers. | script (line counts of every loaded CLAUDE.md, imports, rules) + LLM | [MEM#write-effective-instructions](https://code.claude.com/docs/en/memory#write-effective-instructions); [BP#write-an-effective-claude-md](https://code.claude.com/docs/en/best-practices#write-an-effective-claude-md); [COST#move-instructions-from-claude-md-to-skills](https://code.claude.com/docs/en/costs#move-instructions-from-claude-md-to-skills) |
| C8 | Turn rules that must hold every time into hooks. CLAUDE.md and skills are advisory. | A CLAUDE.md "never/always" rule is violated repeatedly in transcripts. | LLM | [BP#set-up-hooks](https://code.claude.com/docs/en/best-practices#set-up-hooks); [FO "Hook vs Skill"](https://code.claude.com/docs/en/features-overview#compare-similar-features) |
| C9 | Delegate investigation and verbose operations (test runs, log processing, doc fetching) to subagents, so only a summary returns. | **Infinite exploration**: an unscoped "investigate X" in the main thread, followed by dozens of Read/Grep calls or huge tool outputs in the main context. | script (count and bytes of main-thread Read/Grep/Bash output per turn; Agent calls absent) | [BP#use-subagents-for-investigation](https://code.claude.com/docs/en/best-practices#use-subagents-for-investigation); [SA#isolate-high-volume-operations](https://code.claude.com/docs/en/sub-agents#isolate-high-volume-operations); [COST#delegate-verbose-operations-to-subagents](https://code.claude.com/docs/en/costs#delegate-verbose-operations-to-subagents) |
| C10 | Don't over-delegate. Keep iterative back-and-forth, shared-context phases, and quick targeted changes in the main conversation. | A subagent spawned for a one-file edit, or for work that needs the whole conversation's context. Many subagents each returning long reports. | script (subagent transcript size vs. task) + LLM | [SA "When to use subagents"](https://code.claude.com/docs/en/sub-agents) |
| C11 | Ask side questions with `/btw` so the answer never enters history. | Unrelated one-off questions asked mid-task in a working Session. | LLM | [BP#manage-context-aggressively](https://code.claude.com/docs/en/best-practices#manage-context-aggressively) |
| C12 | Name Sessions (`/rename`) and resume (`--continue` / `--resume`) instead of re-explaining. | A Session opens by re-pasting background that an earlier Session already established. | script (Session-opening prompt similarity) + LLM | [BP#resume-conversations](https://code.claude.com/docs/en/best-practices#resume-conversations) |
| C13 | Prefer CLIs (`gh`, `aws`) over MCP where available, and disable unused MCP servers. | MCP servers connected but never called in the Window. MCP calls used where an installed CLI would do. | script (configured servers vs. calls) | [COST#reduce-mcp-server-overhead](https://code.claude.com/docs/en/costs#reduce-mcp-server-overhead); [BP#use-cli-tools](https://code.claude.com/docs/en/best-practices#use-cli-tools) |
| C14 | For long multi-window work, keep state in files (progress notes, a structured test list, git). Starting fresh from that state can beat compaction. | A long task carried across compactions with no progress file or commits, and Claude loses the thread. | LLM | [PE#workflows-across-multiple-context-windows](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#workflows-across-multiple-context-windows); [CE "structured note-taking"](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) |
| C15 | Use a fresh context for review (a writer/reviewer split, or a reviewer subagent). Tell the reviewer to flag only correctness gaps. | Claude reviews its own just-written code in the same context. The opposite also counts: chasing every reviewer nit into over-engineering. | LLM | [BP#run-multiple-claude-sessions](https://code.claude.com/docs/en/best-practices#run-multiple-claude-sessions); [BP#add-an-adversarial-review-step](https://code.claude.com/docs/en/best-practices#add-an-adversarial-review-step) |

## (3) Using skills you have

| # | Practice | Anti-pattern to spot | Detect | Source |
|---|---|---|---|---|
| S1 | Let skills trigger from their description, or invoke one directly with `/skill-name`. Claude matches tasks against descriptions. | A task in the Window clearly matches an installed skill's description, but no Skill tool call or `/name` appears. Claude improvises the procedure instead. | script (keyword match: prompt vs. Toolkit descriptions; Skill calls absent) + LLM to confirm | [FO "How Claude chooses skills"](https://code.claude.com/docs/en/features-overview#understand-how-features-load); [SK "Skill not triggering"](https://code.claude.com/docs/en/skills#skill-not-triggering) |
| S2 | When a skill doesn't trigger, check that its description includes the words users naturally say, then rephrase or invoke it directly. If it triggers too often, narrow the description or set `disable-model-invocation: true`. | A recurring miss on the same skill. A skill invoked in the wrong contexts. | script (per-skill invocation counts) + LLM | [SK#skill-not-triggering](https://code.claude.com/docs/en/skills#skill-not-triggering); [SK#skill-triggers-too-often](https://code.claude.com/docs/en/skills#skill-triggers-too-often) |
| S3 | Write descriptions that say what the skill does and when to use it, in the third person, with specific key terms. Put the key use case first; the listing truncates at 1,536 characters. | Vague descriptions ("Helps with documents"), or descriptions written as "I can help...". | script (lint every SKILL.md description) | [SAB#writing-effective-descriptions](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#writing-effective-descriptions); [SK "description"](https://code.claude.com/docs/en/skills) |
| S4 | Avoid overlapping or vague skills. With overlap, Claude may load the wrong one or miss one. With many skills, the listing budget (1% of the context window) drops descriptions of the least-used skills. | Two skills with near-identical descriptions (this feeds category 9). Skills never invoked across the Window. | script (description similarity; zero-use skills; `/skill-doctor` covers unused skills) | [FO#understand-how-features-load](https://code.claude.com/docs/en/features-overview#understand-how-features-load); [SK#skill-descriptions-are-cut-short](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short) |
| S5 | Re-invoke a skill after compaction, or when Claude stops following it. Compaction keeps only the start of each invoked skill (5k tokens each, 25k total). Put key rules at the top of SKILL.md. | A skill's rules are obeyed early in a Session and dropped after a compaction boundary. | script (skill invoked before a compaction boundary and not after) + LLM | [SK#claude-stops-following-a-skill](https://code.claude.com/docs/en/skills#claude-stops-following-a-skill); [CW#what-survives-compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction) |
| S6 | Use bundled skills and built-ins before hand-rolling: `/code-review`, `/batch`, `/debug`, `/loop`, `/verify`, `/doctor`, and the built-in Explore/Plan subagents. | The user hand-writes a review or fan-out prompt that a bundled skill already covers. | LLM | [SK "Bundled skills"](https://code.claude.com/docs/en/skills); [SA "Built-in subagents"](https://code.claude.com/docs/en/sub-agents) |
| S7 | Set `disable-model-invocation: true` on side-effecting skills. It also keeps their description out of context. | A deploy, commit, or publish-style skill that Claude can auto-invoke. | script (frontmatter check) | [SK "Controlling invocation"](https://code.claude.com/docs/en/skills); [FO#context-cost-by-feature](https://code.claude.com/docs/en/features-overview#context-cost-by-feature) |

## (8) Turning repeated workflows into skills or commands

Custom commands are now skills: `.claude/commands/x.md` and `.claude/skills/x/SKILL.md` both create `/x` ([SK](https://code.claude.com/docs/en/skills)). A Retro should propose skills, not a separate commands format.

| # | Practice | Anti-pattern to spot | Detect | Source |
|---|---|---|---|---|
| W1 | Save a prompt you keep typing to start a task as a user-invocable skill. | Near-identical opening prompts across Sessions (from `history.jsonl` and first user turns). | script (cluster prompt text) | [FO#build-your-setup-over-time](https://code.claude.com/docs/en/features-overview#build-your-setup-over-time) |
| W2 | When you paste the same playbook, checklist, or multi-step procedure for the third time, capture it as a skill. | The same multi-step instruction block appears 3+ times in the Window. | script (shingle/near-duplicate detection on long user messages) | [FO#build-your-setup-over-time](https://code.claude.com/docs/en/features-overview#build-your-setup-over-time); [SK "When to create a skill"](https://code.claude.com/docs/en/skills) |
| W3 | Move a CLAUDE.md section that has grown into a procedure to a skill. Skill bodies load only when used. | A CLAUDE.md with step-by-step workflows (PR review, migrations) loaded in every Session. | script (numbered-list blocks in CLAUDE.md) + LLM | [SK "When to create a skill"](https://code.claude.com/docs/en/skills); [MEM#when-to-add-to-claude-md](https://code.claude.com/docs/en/memory#when-to-add-to-claude-md); [COST#move-instructions-from-claude-md-to-skills](https://code.claude.com/docs/en/costs#move-instructions-from-claude-md-to-skills) |
| W4 | Define a custom subagent when you keep spawning the same kind of worker with the same instructions. | Repeated Agent calls whose prompts are near-identical. | script (cluster Agent prompts) | [SA "When to use subagents"](https://code.claude.com/docs/en/sub-agents) |
| W5 | Turn something that must happen every time without asking into a hook, not a skill. | Every Session ends with the user asking "run lint/format/tests" by hand. | script | [FO#build-your-setup-over-time](https://code.claude.com/docs/en/features-overview#build-your-setup-over-time); [FO "Hook vs Skill"](https://code.claude.com/docs/en/features-overview#compare-similar-features) |
| W6 | Treat a workflow you keep tweaking by hand as a skill that needs another revision. | A skill is invoked, then followed by the same manual adjustment each time. | LLM | [FO#build-your-setup-over-time](https://code.claude.com/docs/en/features-overview#build-your-setup-over-time) |
| W7 | Build the skill from a real Session. After finishing a task, ask Claude to capture the reusable pattern as a skill, then test it in a fresh instance. Write minimal instructions aimed at observed gaps. | (Guidance for the Finding's "apply" step, not a detection signal.) | n/a | [SAB#develop-skills-iteratively-with-claude](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#develop-skills-iteratively-with-claude); [SAB#build-evaluations-first](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#build-evaluations-first); [AS](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) |
| W8 | Keep the proposed skill concise: under 500 lines, references one level deep, scripts for deterministic steps, and `disable-model-invocation: true` if it has side effects. | (Quality bar for skills a Retro proposes.) | n/a | [SAB#concise-is-key](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#concise-is-key); [SK](https://code.claude.com/docs/en/skills); [AS](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) |
